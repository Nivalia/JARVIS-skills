# Security checklist for internet-exposed CouchDB

CouchDB has **no built-in rate limiting, no brute-force protection, and no automatic patching.** If your LiveSync instance is on a public IP, attackers can:

- Brute-force the admin password (32 hex chars from `openssl rand -hex 16` is enough; anything shorter is crackable)
- Enumerate `_all_dbs` to learn your vault name
- DOS you out by spamming PUT requests (CouchDB is single-threaded Erlang, slow under load)
- Read your vault if they steal your SSH key OR if your CouchDB user password is weak

This checklist is the minimum for a single-user self-host.

## 1. Network-level

### Restrict the public-facing port

```bash
# Cloud security group (Aliyun / Tencent / AWS / GCP): allow ONLY your IPs
# Example for a single home IP: 1.2.3.4/32

# Or on the host with ufw
ssh root@<server-ip] 'ufw allow from 1.2.3.4 to any port 8443 proto tcp'
ssh root@<server-ip] 'ufw enable'

# Or iptables
ssh root@<server-ip] 'iptables -A INPUT -p tcp --dport 8443 -s 1.2.3.4 -j ACCEPT'
ssh root@<server-ip] 'iptables -A INPUT -p tcp --dport 8443 -j DROP'
```

**CouchDB binds 127.0.0.1:5984** so it's NOT directly exposed — nginx IS the only public-facing entry. So restricting 8443 is sufficient.

### Restrict SSH to your IP (same idea)

```bash
# Cloud security group: only your IP on port 22
# OR
ssh root@<server-ip] 'ufw allow from 1.2.3.4 to any port 22 proto tcp'
```

### fail2ban for SSH

```bash
ssh root@<server-ip] 'apt install -y fail2ban
cat > /etc/fail2ban/jail.local <<EOF
[sshd]
enabled = true
port = ssh
filter = sshd
logpath = /var/log/auth.log
maxretry = 3
bantime = 3600
EOF
systemctl enable --now fail2ban'
```

## 2. CouchDB-level

### Use a strong admin password

```bash
# Already done in the deploy. Verify:
ssh root@<server-ip] 'cat /opt/couchdb/etc/admin_pass | head -c 32; echo'
# 32 hex chars = 128 bits of entropy — uncrackable

# If you used a short password, regenerate:
ADMIN_PASS=$(openssl rand -hex 16)
echo $ADMIN_PASS | ssh root@<server-ip] 'cat > /opt/couchdb/etc/admin_pass'
ssh root@<server-ip] 'docker restart couchdb'
```

### Use a separate user password (also strong)

```bash
# Same: 32 hex chars
USER_PASS=$(openssl rand -hex 16)
echo $USER_PASS | ssh root@<server-ip] 'cat > /opt/couchdb/etc/user_pass'

# Re-register the user with the new password
ssh root@<server-ip] "curl -s -X PUT -u admin:\$(cat /opt/couchdb/etc/admin_pass) \
  http://127.0.0.1:5984/_users/org.couchdb.user:<USERNAME> \
  -H 'Content-Type: application/json' \
  -d '{\"name\":\"<USERNAME>\",\"password\":\"<USER_PASS>\",\"roles\":[],\"type\":\"user\"}'"
```

### Don't enable `_all_dbs` for unauthenticated users

By default, CouchDB allows anyone (no auth) to GET `/_all_dbs`. This reveals your vault name.

```bash
# Test from public:
curl -sk https://<server-ip>:8443/_all_dbs
# expect: ["_replicator","_users","<VAULT_NAME>"]

# The vault name reveal is OK if it's unguessable (e.g. "aeglx-vault-2026").
# If you want to hide it, use a randomized name like:
ssh root@<server-ip] "curl -s -X PUT -u admin:<ADMIN_PASS> \
  http://127.0.0.1:5984/obsidian-vault-\$(openssl rand -hex 8)"
```

### Disable CORS wildcards (only if you don't need cross-origin clients)

```ini
# /opt/couchdb/etc/local.ini — replace '*' with your specific origin
[cors]
origins = https://your-vault-domain.com
```

For mobile + desktop Obsidian clients, CORS isn't used (they're not browsers). Wildcards are fine.

## 3. Application-level (Obsidian)

### End-to-end encryption passphrase

- 20+ characters, ideally generated by your password manager
- NEVER in any git repo, env file, or shell history
- If you forget it: **your vault is unrecoverable**. Treat it like a master password.

### Don't store secrets in plain notes

Even though LiveSync encrypts client-side, anyone with your SSH key + admin password can:
- Decrypt nothing (because of the passphrase) — IF your passphrase is strong
- Read your plaintext notes IF you have weak passphrase or passphrase leaked elsewhere

Don't put API keys, passwords, tokens in notes unless you're prepared to manage the encryption carefully. Use `.env` files or a password manager instead.

## 4. Operational

### Daily backup of /opt/couchdb/data

```bash
ssh root@<server-ip] 'cat > /opt/couchdb/backup.sh <<EOF
#!/bin/bash
set -e
BACKUP_DIR=/opt/couchdb/backups
mkdir -p $BACKUP_DIR
DATE=\$(date +%Y%m%d-%H%M%S)
tar czf $BACKUP_DIR/couchdb-\$DATE.tar.gz -C /opt/couchdb data
# Keep last 30 days
find $BACKUP_DIR -name "couchdb-*.tar.gz" -mtime +30 -delete
EOF
chmod +x /opt/couchdb/backup.sh
crontab -l 2>/dev/null | { cat; echo "0 3 * * * /opt/couchdb/backup.sh"; } | crontab -'
```

Test the restore procedure BEFORE you need it:
```bash
ssh root@<server-ip] 'mkdir -p /tmp/couchdb-restore-test
tar xzf /opt/couchdb/backups/couchdb-YYYYMMDD-*.tar.gz -C /tmp/couchdb-restore-test
ls /tmp/couchdb-restore-test/data | head'
# Should show .delete, _replicator.couch, _users.couch, <vault>.couch
```

### Monitor logs for anomalies

```bash
ssh root@<server-ip] 'tail -F /var/log/nginx/access.log | grep -v "liveSync\|/_changes\|/_replicator"'
# Most legit traffic hits /<vault>, /_changes, /_replicator
# Random 401s from unknown IPs = someone brute-forcing your admin/user

ssh root@<server-ip] 'docker logs couchdb 2>&1 | grep -i "unauthorized\|error" | tail -20'
```

### Plan for the worst case

- **Stolen SSH key**: revoke the old public key on the server, generate a new keypair, repeat the deploy
- **CouchDB admin password leaked**: rotate it (see above), then rotate the user password, then re-register the user in `_users`
- **Encryption passphrase lost**: your vault is unrecoverable from CouchDB. Restore from `/opt/couchdb/backups/` directly into the file system and continue from there

## TL;DR minimum hardening (5 minutes)

If you only do 5 things, do these:

1. Restrict port 8443 to your IPs in the cloud security group
2. Use `openssl rand -hex 16` for both admin and user passwords
3. Use a 20+ char encryption passphrase in LiveSync, store in password manager
4. Set up the daily backup cron
5. Disable password SSH auth (only key-based)
